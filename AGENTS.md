## Accepted build preservation gate (owner rule, 2026-11-28)
An accepted Windows build is NOT closed until the artifact that was actually accepted is preserved in this repository. For every accepted build of J2534Diag.exe, run `tools/preserve_build.py` with `--product j2534diag` as the final acceptance step, wherever the accepted artifact exists — for CI builds, that means downloading the exact accepted package first; a hash recorded in an acceptance record is not a preserved build (full procedure: `docs/BUILD_PRESERVATION.md`). The script verifies the artifact SHA-256 against the acceptance record, commits the .exe or its release .zip to `preserved-builds/j2534diag/v<version>/` with its `SHA256SUMS.txt` as `release: preserve j2534diag v<version> build [skip ci]`, and pushes. The `preserved-builds/` tree always holds at least the last two preserved versions; older folders rotate out of the tree (they stay in git history). A preserved build is immutable — never overwrite one under the same version. A branch carrying a preserve commit is not deleted until that commit reaches `master`. GitHub Releases attachments and Actions artifacts do NOT satisfy this gate: they live outside git and never reach the owner's mirrors. Documentation-only edits: `[skip ci]`.
